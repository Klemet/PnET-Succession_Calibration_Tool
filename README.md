## 🎯 Objective

- This repo contains a set of Jupyter Notebooks used to parameterize and calibrate different tree species in a given study area for the [PnET Succession Extension](https://github.com/LANDIS-II-Foundation/Extension-PnET-Succession) of the [LANDIS-II Forest Landscape Model](https://www.landis-ii.org/).
- The calibration process used here is mostly based on the [calibration tips](https://research.fs.usda.gov/about/people/gustafson) of Eric Gustafson, available in the [PnET Succession v5.1 user guide](https://github.com/LANDIS-II-Foundation/Extension-PnET-Succession/blob/master/deploy/docs/LANDIS-II%20PnET-Succession%20v5.1%20User%20Guide.pdf).
- **💡 One of the main objectives here is to make this calibration process transparent and replicable, so as to facilitate future studies that will want to use PnET in different contexts, or with future versions**.
- **⚠ The notebooks in this repository were made as a "Proof of concept", calibrating 6 different tree species in a landscape situated in the province of Quebec, in Canada**. However, you can copy/fork these notebooks and modify them to calibrate your own species in your own landscape.
- **⚠  The notebooks, scripts and functions made in this repository are currently using Canadian datasets** (the [Ouranos CRCM5-CMIP6 ensemble](https://www.nature.com/articles/s41597-025-06289-7) for climate data, the [Canadian National Forest Inventory data](https://nfi.nfis.org/en/) for the empirical growth curves, etc.). However, you can create new functions or adapt the existing ones so as to use datasets from other countries, and even different approaches. Using AI to generate Python code or functions can speed up your work for this, and you can give the existing functions (see `functionsForCalibration.py`) to your AI model so that it can match the format used in the notebooks. Simply be careful to double-check what you're doing.
- This effort was made  [research theme 4](https://diverseproject.uqo.ca/theme-4-evaluation-various-forest-management-approaches/) of the pan-canadian [DIVERSE research project](https://diverseproject.uqo.ca), where several Functional Management Unit of Canada will be simulated with different forest management strategies.
- See the next section ⚙ **How to use** in order to deploy all of the files and programs used for this calibration on your computer. The process should be relatively simple. Feel free to [post an issue](https://github.com/Klemet/Calibration_PnET_DIVERSE/issues) if you encouter a problem.

## 💻 How to run it on your computer

- Install Docker Desktop on your computer (https://www.docker.com/products/docker-desktop/) or simply install Docker if you are using Linux.
- Clone or download the contents of this repository on your computer (Code => Download zip, or cloning the repository in another way).
- Unzip, and then launch the file `buildDockerImage.ps1` in a powershell (if you're on windows), `buildDockerImage.sh` if you're on linux. You can also open a terminal, then go to the folder `Clean_Docker_LANDIS-II_8_AllExtensions_PnETCalibration` to launch the command `docker build -t landis_ii_v8_calibration_pnet ./` to build the docker image. The Docker image that will be built contains everything needed to re-do the calibration I've done here in a replicable way (including Jupyter lab to see read and act on the Jupyter notebooks file which have been used to create the Jupyter Book available [here](https://klemet.github.io/Calibration_PnET_DIVERSE/)), and of course, LANDIS-II. The `Dockerfile` file contain all of the commands used to build the image, and comments about what versions of the LANDIS-II extensions are installed. The image is made in a two-step build; first downloading an image from the [Tool-Docker-Apptainer](github.com/LANDIS-II-Foundation/Tool-Docker-Apptainer) repository (which are updated frequently), and then adding the python packages needed to run the functions and Jupyter lab used for the calibration.
- Once the build is over, run the file `launchDockerCalibrationPnet.ps1` in a powershell (if you're on windows), or `launchDockerCalibrationPnet.sh` if you're on linux. You can also run the command by yourself in a terminal : `docker run -it -p 8888:8888 --mount type=bind,src="<CALIBRATION_FOLDER_PATH>",dst=/calibrationFolder landis_ii_v8_calibration_pnet`, replacing `<CALIBRATION_FOLDER_PATH>` with the full path to where the folder `Calibration_PnET_DIVERSE` is on your computer. It is advised that you keep the bind to `/calibrationFolder` in the container as is the case in this command, as Jupyter lab is configured to look there for its configuration files.
> ⚠️ **If you close the terminal where you have entered the `docker run` command, the Docker container will close down with it !**
- Jupyter lab will automatically launch when launching the container. Simply click on the URL that it gives you (that will look like `http://127.0.0.1:8888/lab?token=<LONG TOKEN>`) or copy/paste it in your favorite web browser.
- In Jupyter lab, use the navigation pannel on the left to go to `/calibrationFolder` to open the Jupyter notebooks corresponding to the part of the calibration you are interested in. You can normally run every cell without any compatibility issue from here.
- If you are using these files for your own calibration process, and if you need to add/update Python packages to the docker image to use them in the notebook, you can quit the jupyter lab instance and use `pip` to install them. However, these will be temporary. Editing the `Dockerfile` to add the `pip install ...` commands you need at the end and then re-building the image will make things permanent.

## 🛠️ Technical notes about using the docker image and building the jupyter book used in this repository

- When building the Docker image used to run everything in this repository, the program `pip` is used to install the packages necessary for the notebooks to execute. In order to make the notebook future-proof and avoid a situation where commands are not working anymore because of package updates, I first installed all of the packages while letting pip choose the versions it wants for each (to resolve the dependancies between packages); then, testing if this combination of packages works with the notebook; then, exporting the specific versions for each package with the command `pip freeze` in a text file. This text file is then used to build the Docker image (`pip_requirements.txt`).
    - As such, **if you need to install new packages**, you might need to edit the Dockerfile to use `pip_requirements_NotFreezed.txt` where the versions are not specified so that pip can resolve the dependancies of your new package combined with the others. Just replace `pip_requirements.txt` by `pip_requirements_NotFreezed.txt` in the Dockerfile and add your new package to `pip_requirements_NotFreezed.txt`. **If you don't do this, pip might become unable to resolve the package dependencies when building the Docker image, and you might get an error**.
- Don't try to stage files with git or create git commit while you are running the Jupyter lab server on your computer. **This will likely results in errors in git where git will become unable to find some of the files in your folders, even though they exist**.
- Use `BuildAndUpdateJupyterBook.ipynb` in Jupyter lab to re-create the Jupyter Book, whose file will be put into `/docs`. Pushing a commit with new files in `/docs` will re-create the book. You can host this Jupyter Book (which is a collection of HTML pages) easily as a static website using Github pages. See the documentation on [Github pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) or ask an AI model for help. This static website will allow you to share your methodology transparently and easily with colleagues or reviewers.

## 🔁 About updating the Docker image in the future (i.e. for future versions of PnET-Succession)

The current version of the Docker image uses PnET-Succession v6.1 and LANDIS-II v8.

If you're using this repository in the future, many LANDIS-II updates and Python updates might have been done in the meanwhile. To be certain that you're calibrating things for the latest version of PnET-Succession that you're going to use in your simulations, you need to update the Docker image before running this tool again.

Making the update will not be too difficult. Open the file `Dockerfile` in `Clean_Docker_LANDIS-II_8_AllExtensions_PnETCalibration`, and edit the argument BASE_IMAGE to take the most recent version of the right docker image at https://github.com/orgs/LANDIS-II-Foundation/packages?repo_name=Tool-Docker-Apptainer. Be certain to indicate the right sha256 (the unique identifier for a particular build of a given image name).

Then, if you want to update the python packages too (this is most likely not needed, you can keep them as they are currently) edit the contents of `files_to_help_compilation/pip_requirements.txt` so that it contains the inside of the file `pip_requirements_NotFreezed.txt`. This will "unfreeze" the version of the python packages during the build, letting pip resolve them differently with more recent versions. This resolution might come with bugs and issues, requiring some tweaks before the image build successfully. You can then re-freeze by generating the list of the particular version of each package that pip has installed, and putting it back inside `pip_requirements.txt`.

Updating LANDIS-II should not lead to conflicts or issues with the calibration tool, except if some parameter names in PnET-Succession are changed, or new parameters added or removed. If that's the case, you will have to edit the functions of the calibration tool or the content of the Jupyter notebooks in consequence. If you decide to update the Python packages too, you might get a lot of little issues to fix in the Python functions used in the notebooks.

Good luck !
